# 설비 예지보전: 잔여수명(RUL) 예측

항공엔진 센서 시계열(NASA C-MAPSS FD001)로 **잔여수명(Remaining Useful Life)** 을
예측한다. 그리고 공장 입장에서 가장 중요한 부분 — 단순 오차가 아니라 예지보전의
**비용 구조**로 모델을 평가하는 것 — 까지 다룬다.

> [English README](./README.md) · **한국어**

---

## 1. 문제 정의

엔진 센서값의 흐름이 주어졌을 때, 고장까지 **몇 사이클** 남았는지를 예측한다. 정답이
숫자이므로 분류가 아니라 **회귀**다. 고장을 미리 예측하면 정비를 계획해 계획되지 않은
가동 중단·2차 파손·안전사고를 막을 수 있다 — 예지보전의 핵심 가치다.

프로젝트 전체를 관통하는 반전: **두 종류의 실수는 비용이 다르다.** 수명이 실제보다
많이 남았다고 보는 *늦은 예측* 이, 적게 남았다고 보는 *이른 예측* 보다 훨씬 위험하다.
RMSE는 이 차이를 못 보지만 공장은 안다. 이 **비대칭** 을 다루는 것이 이 프로젝트의
심장이다.

## 2. 데이터

- **출처:** NASA C-MAPSS Turbofan Engine Degradation, 그중 **FD001** (단일 운전조건,
  단일 고장모드).
- **구조:** 학습셋은 고장까지 기록된 엔진 100대(20,631행). 한 행은 한 엔진의 한 사이클
  이며, 운전조건 3개와 센서 21개가 담긴다. train 엔진은 **고장까지**, test 엔진은 고장
  **전에 잘려** 있고, 실제 잔여수명은 `RUL_FD001.txt`에 따로 주어진다.
- **엔진 수명** 은 128~362 사이클(평균 약 206).
- **전처리:** 값이 안 변하는 상수 센서 6개(`s1, s5, s10, s16, s18, s19`)를 제거해 15개
  사용, **train 기준** 으로 [0, 1] 정규화, RUL 상한 **125** 로 클리핑.

**왜 RUL을 125에서 자르나?** 엔진 초반에는 센서에 마모 신호가 없어서, 건강한 센서값만
보고 "190 사이클 남았다"를 맞히는 건 불가능하고 무의미하다. 클리핑은 "수명이 넉넉히
남은 구간은 그냥 '충분히 건강함'이라는 하나의 상한으로 취급하자"는 뜻이다. 꼼수가
아니라 열화 물리에 기반한 모델링 판단이다.

## 3. 시계열 전처리 — 슬라이딩 윈도우

한 사이클의 스냅샷만으로는 *추세* 를 알 수 없다. 시계열의 정보는 "값이 어떻게
변하는가"에 있으므로, 최근 **N = 30** 사이클을 하나의 입력으로 묶어
`[샘플 수, 윈도우 길이, 센서 수]` 3차원 텐서로 만든다.

정확성을 좌우하는 단 하나의 규칙: **윈도우는 엔진 경계를 넘지 않는다.** 한 엔진의
끝과 다른 엔진의 시작을 한 창에 담으면 존재하지 않는 가짜 궤적을 만들어 시계열이
오염된다. 그래서 창은 *엔진별로만* 슬라이딩한다. 완성된 창끼리는 학습 시 자유롭게
섞어도 되는데, 창 *안* 의 시간 순서는 이미 고정돼 있기 때문이다.

test는 각 엔진의 **마지막 창** 하나를 샘플로 쓰고, 엔진을 정렬 순서로 돌아 예측과
`RUL_FD001.txt`의 순서를 맞춘다.

## 4. 모델

**1D-CNN**(`Conv1d`)이 작은 필터를 **시간축을 따라** 미끄러뜨리며 국소 열화 패턴(예:
온도 급상승)을 잡는다. 구현을 좌우하는 함정 하나: PyTorch `Conv1d`는 입력을
`[배치, 채널, 길이]`로 기대하고 **센서를 채널, 시간을 길이** 로 본다. 그래서 forward
에서 `permute`로 마지막 두 축을 바꾼 뒤 합성곱한다. 이어 `AdaptiveAvgPool1d`로 시간축을
채널당 값 하나로 요약하고, 선형층이 RUL 하나를 출력한다. 손실은 `MSELoss` — 회귀이므로
sigmoid/softmax 없이 숫자를 그대로 낸다.

학습 루프는 모든 지도학습 프로젝트에서 쓴 `zero_grad → forward → loss → backward →
step` 그대로이고, 바뀌는 건 모델(시퀀스)과 손실(MSE)뿐이다.

## 5. 평가 — RMSE + 비대칭 비용

두 숫자를 **함께** 읽는다:

- **RMSE — 22.24 사이클.** 베이스라인은 평균 약 22사이클 틀린다. 수명 약 200사이클에
  비하면 쓸 만한 첫 모델이지 강한 모델은 아니다. RMSE는 대칭이라 +15와 −15를 똑같이
  센다.
- **C-MAPSS 표준 점수 — 4566.** 늦은 예측(과대예측)에 `exp(d/10)−1`, 이른 예측에
  `exp(−d/13)−1`을 적용해 **늦은 예측에 더 큰 벌점** 을 주는 필드 표준 지표. 낮을수록
  좋다.

**오차 방향 분석(핵심 통찰).** `오차 = 예측 − 실제` 로 정의하면:

- `오차 > 0` → 과대예측 → 정비를 미룸 → 가동 중 고장 위험. **위험.**
- `오차 < 0` → 과소예측 → 멀쩡한 부품을 조기 정비 → 부품 낭비지만 **안전.**

베이스라인은 100대 중 **66대** 에서 과대예측(평균 +18사이클)했고, 과소예측은 34대(평균
−12)였다. 즉 모델이 **위험한 늦은** 쪽으로 치우쳐 있다 — 정비 엔지니어가 가장 피하고
싶은 방향이고, 다음 단계의 동기가 된다.

## 6. 개선 실험

한 번에 하나씩만 바꿔 비교했다(간결한 비교를 위해 test로 측정했으나, 엄밀히는 val로
선택하는 것이 원칙):

| 실험 | RMSE | C-MAPSS 점수 |
|---|---:|---:|
| 베이스라인 (window = 30, MSE) | 22.24 | 4566 |
| window = 20 | 20.77 | 2798 |
| window = 50 | 24.82 | 6160 |
| dropout = 0.3 | 21.17 | 2764 |
| **비대칭 손실 (2×)** | **20.74** | **2192** |

**짧은 윈도우(20)** 와 **드롭아웃** 은 소폭 도움이 되고, 긴 윈도우(50)는 오히려
나빠진다 — 맥락이 길다고 항상 좋은 건 아니다. 가장 큰 개선은 비대칭 손실에서 나온다.

### 비대칭 손실 — 지표를 내주고 현실 비용을 얻기

MSE는 대칭이지만, 손실 자체를 비대칭으로 만들면 모델이 학습 단계부터 위험한 *늦은
예측* 을 피하도록 유도할 수 있다. 과대예측 오차에 **2배** 가중치를 준 손실을 썼을 때:

| | 늦은/위험 | 이른/안전 | RMSE | C-MAPSS |
|---|---:|---:|---:|---:|
| 베이스라인 (MSE) | 66 | 34 | 22.24 | 4566 |
| 비대칭 손실 | 47 | 53 | 20.74 | 2192 |

오차 분포가 **안전한** 쪽으로 이동하고(위험한 예측 66 → 47), C-MAPSS 점수가 절반 이하로
떨어진다. 여기서는 RMSE도 마침 좋아졌지만, 설령 RMSE가 조금 나빠졌더라도 이 선택은
정당하다: 예지보전에서는 위험한 늦은 예측의 건수를 줄이는 것이 대칭 오차 지표의 작은
손해보다 값지다. **헤드라인 지표를 좇는 대신, 비용에 맞는 목적함수를 최적화하는 것** 이
핵심이다.

## 7. 배운 점

- 원본 시계열을 **엔진 경계를 지키는 슬라이딩 윈도우** 로 모델이 먹는 텐서로 바꾸는
  법, 그리고 그 경계 규칙이 왜 타협 불가인지.
- **1D-CNN** 이 시퀀스를 읽는 방식, 특히 대부분의 첫 구현이 걸려 넘어지는 채널/시간 축
  교환.
- 회귀를 RMSE만이 아니라 **도메인 비용함수**(C-MAPSS 비대칭 점수)와 함께 평가하고,
  오차의 크기뿐 아니라 **방향** 까지 읽는 법.
- **지표와 실제 비용이 어긋날 때** 의 판단: 위험한 늦은 예측을 없앨 수 있다면 약간의
  RMSE 손해는 올바른 공학적 선택일 수 있다.

**한계 / 다음 단계.** FD001은 가장 쉬운 부분집합(단일 운전조건)이다. FD002/FD004는
운전조건 복잡도가 더해진다. LSTM 비교, 엔진 단위 early stopping, 과대예측 벌점을 test가
아닌 val로 튜닝하는 것 등이 자연스러운 확장이다.
